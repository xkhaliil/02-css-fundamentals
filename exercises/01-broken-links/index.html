Debug

Five pages, five crimes

Every page below tries to load the same stylesheet, css/style.css. That file is fine. On each page exactly one thing is wrong with how it's connected. Find it.

Your tools
  1. View source (⌘ ⌥ U / Ctrl U) — read the <head>. Click the href: does it open the file?
  2. DevTools → Network, reload. Is style.css there? Red 404 = wrong path.
  3. DevTools → Elements → Styles. Pick <body>. Do you see rules from style.css?

Answers (no peeking)

Page A

<link href="css/style.css"> has no rel="stylesheet". A <link> can point at icons, fonts, feeds… without rel the browser doesn't know it's a stylesheet, so it never downloads it.

Page B

href="style.css" looks for the file next to the HTML. It lives in css/. Network tab shows a 404. Paths are relative to the HTML file.

Page C

<style src="…"> is not a thing. <style> holds CSS written inside it; to load a file you need <link rel="stylesheet" href="…">. (src is for <script> and <img>.)

Page D

The file loads (Network: 200 ✓) and the stamp says "connected" — but the page isn't yellow. Open css/pasted.css: someone copied <style> tags into a .css file. The browser reads <style> body as one broken selector and silently drops the whole first rule. Everything after it still works. CSS fails quietly, one rule at a time.

Page E (bonus)

It works on your Mac… The file is style.css, the link says Style.css. macOS and Windows don't care about capital letters in file names; the Linux servers behind most hosting (GitHub Pages included) do. Deploy it and it breaks. Keep file names lowercase.
