Cascade

Win the fight. Fairly.

In every round, a rule you can't touch is already in the stylesheet. Add CSS after it in the editor so your colour wins. Each round has a rule of engagement. In class: rounds 1–2 right after the verdict on the stubborn button (Ex 4a), round 3 after inheritance (Ex 4b). Rounds 4–6 are homework.

Round 1

The tie-break

Make the heading tomato. No ids, no !important.

Why it works

Writing .hero h1 again gives you (0,1,1) against (0,1,1). A tie. When specificity ties, order of appearance decides: the rule that comes last wins. h1 alone (0,0,1) would lose, even though it comes later.

Round 2

Beat the id

Make the paragraph tomato. No !important. Try ten classes first, just to feel it fail.

Why it works

Specificity is compared column by column, left to right. (1,0,1) beats (0,99,0) because the id column is checked first. You need an id too: #promo p again (tie → you're later), or #promo .lead (1,1,0). Lesson: ids in CSS start arms races. Style with classes.

Round 3

The inheritance trap

Make all the text in the card tomato. Start with the line that's already there — why does only the heading change?

Why it works

Inheritance only fills the gaps. The <p> has its own rule, p { color: #555 }, and any rule that targets an element directly beats a value it would inherit from its parent — even a weak (0,0,1) rule. Target the paragraph itself: .card p.

Round 4

Zero power

Make the link tomato using only type selectors — no classes, no ids, no pseudo-classes.

Why it works

:where() matches like normal but adds nothing to specificity. The locked rule is only (0,0,1). Your a is also (0,0,1) and comes later → it wins. Libraries use :where() so their defaults are easy to override.

Round 5

The inline style

Make the button's background tomato. You can't edit the HTML. The starting line already uses an id and three classes — and still loses. Anything goes.

Why it works

A style="" attribute sits above every selector in the cascade — no amount of ids beats it. !important jumps a whole level up the cascade. Use it here, where you truly can't touch the source (third-party widgets, CMS output). Almost nowhere else.

Round 6

Layers

Make the button tomato with the plain selector .button. Impossible against an id? Read the locked code carefully.

Why it works

Cascade layers are checked before specificity. CSS that isn't in any layer beats CSS inside a layer, whatever the selectors. .button { background: tomato } is enough. Layers let you decide the winners on purpose, instead of fighting with longer selectors.
